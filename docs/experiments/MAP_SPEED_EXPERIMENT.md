## 실행

다른 제어/송신 코드를 먼저 종료하고 MORAI 센서·Competition Status UDP를 켭니다.
아래 명령은 **차량을 실제로 시뮬레이터에서 움직입니다**. 기존 runner가
Manual → I → P 초기화, 초기 좌표·정지 상태 확인 후 한 바퀴를 실행합니다.
RViz와 rosbag 기록을 포함하고, 완주 또는 최대 260초/중단 조건에서 정지합니다.

```bash
bash ~/molit-2026-stier1-suhyeon/run_map_speed_demo.sh 100
```

고주로 목표를 낮춰 같은 흐름을 확인하려면 마지막 인자를 `80`으로 바꿉니다.
기존 59 km/h 목표/60 상한 데모는 아래 명령 그대로입니다.

```bash
bash ~/molit-2026-stier1-suhyeon/run_team_demo.sh
```

## 속도 결정

- RDDF는 XYZ만 제공합니다. RDDF가 선택한 Lanelet과 기존 경계 보정의 점별
  source_link_id를 그대로 사용하며 경로 XY, 조향 비용/게인, 오프셋은 바꾸지 않습니다.
- 일반 구간: 지도 규정 60 km/h, 추종 여유를 둔 계획 목표 최대 59 km/h.
- 고주로: 지도 규정은 여전히 무제한이며 **시험 목표/운용 상한만 최대 100 km/h**.
- 최종 목표는 지도 속도 계획, 기존 곡률/횡가속도, 차선 여유 및 heading 제한 중
  낮은 값입니다. 100을 지정해도 곡률 등으로 실제 목표가 더 낮아질 수 있습니다.
- 고주로 진출은 전방 200 m에서 일반 구간을 조회하여 1.7 m/s² 감속 가정 및
  20 m 여유로 미리 감속합니다. 진입/진출에는 앞뒤 차체를 위한 보수적 여유도 둡니다.
- 고속 시험의 local path는 300 m이며, 측정 속도 60 km/h 초과 시 기존 곡률
  preview를 감속거리 + 20 m까지 확장합니다. 기존 조향 horizon/가중치는 유지합니다.
- 경로·odometry·지도 속도 메시지를 같은 stamp로 처리합니다. 누락/오래됨/잘못된
  구간 속도는 기존 안전 제동으로 연결됩니다. PID fallback에도 지도 상한 제동을
  적용합니다. 일반 구간 제동 개입 59.5 km/h, 고주로는 선택한 시험 상한입니다.
- 어댑터의 102 km/h 입력 범위와 runner의 상한+2 km/h 중단 여유는 **허용 주행속도나
  목표가 아닙니다**. 과속은 물리적으로 이미 발생할 수 있으므로 안전 보장이 아닙니다.

기존 횡오차 0.8 m 중단 기준은 차체가 차선을 밟지 않는다는 보장이 아닙니다.
이번 변경에는 앞/뒤 오버행의 예측 경계 제약이나 고속 MPC 재튜닝을 넣지 않았습니다.

## 확인 범위

시뮬레이션/UDP 송신은 실행하지 않았습니다. 빌드, 단위 테스트 및 지도 데이터 기반
오프라인 검사를 통과했다고 해서 **100 km/h에서 안정적이라고 검증된 것은 아닙니다**.
곡률 속도 계산의 횡가속도 상한 2.6 m/s²만 보더라도 100 km/h 유지에는 대략
곡률 0.00337 1/m 이하(반경 약 297 m 이상)가 필요합니다. 이는 운동학적 계산이며
타이어·횡동역학·추종 성능·급제동은 실제 시뮬레이션 기록으로 별도 확인해야 합니다.

재현 가능한 오프라인 검사:

```bash
cd ~/molit-2026-stier1-suhyeon
/usr/bin/python3 -B src/morai_kcity_hd_map/scripts/check_map_speed.py
source /opt/ros/noetic/setup.bash
PATH=/opt/ros/noetic/bin:/usr/bin:/bin catkin_make run_tests_morai_path_tracking_gtest_test_curvature_speed_planner -j2
```

속도 플래너 16개 테스트(지도 상한의 필터/변화율 우선순위, 고속 원거리 곡선 포함),
실제 경로 4,391점/39 Lanelet의 지도 속도 검사, 초기화 주차 조건 검사,
60/80/100 km/h launch 설정 해석 검사를 사용했습니다. 실행 시 `raw.bag`의
`/route_speed_limit`과 `/control/controller_status`, `resolved_route.yaml`,
`resolved_adapter.yaml`, `run.json`에 구간 상한·최종 목표·실제 속도를 남깁니다.

완전한 소스 롤백은 프로세스를 종료한 뒤 변경분을 먼저 보존하고 `main`으로
체크아웃하여 **이 단일 워크스페이스를 다시 빌드**해야 합니다. 브랜치만 바꿔서는 이미
설치된 바이너리가 되돌아가지 않습니다.
